# 硬件适用范围与验证方法

自动测试使用独立配置和自有窗口，不改用户录制设置或系统默认声卡，不卸载 / 禁用显卡驱动。

| --- | --- | --- |
| RTX 2060，NVENC 无损 / H.264 / HEVC | 三模式标准探测试编码通过；实际 2560×1440 / 30 FPS 编码，保护块严格独立解码通过 | 其他 NVIDIA 型号、驱动、4K / 高帧率和编码会话耗尽 |
| RTX 2060，HEVC 10-bit 4:4:4 编码无损 | Rext / yuv444p10le / BT.709 全范围；编码前后 YUV 哈希一致，奇数尺寸、缩放、MP4、连续分段与暂停/继续通过；实际 2560×1440 / 30 FPS 编码的各保护块格式与严格解码通过 | 其他 NVIDIA 型号、4K / 高帧率；RGB 转换非逐像素保证，非 HDR 捕获 |

## 自动专项

在包含源码和 .NET SDK 的项目根目录执行（便携包没有测试源码，便携版可通过「设备诊断」和下列手动步骤验收）：

```powershell
powershell -ExecutionPolicy Bypass -File tests/Run-Regression.ps1 -Platform
powershell -ExecutionPolicy Bypass -File tests/Run-Regression.ps1 -Platform -Seconds 7200
```

第二条会真实等待两小时，并创建自有全屏测试目标窗口，默认使用主屏原始尺寸、30 FPS、可用 NVIDIA H.264 或 CPU H.264、默认 WASAPI 声音。测试会运行编译、显卡试编码、时钟模拟、跨屏界面、实录和整段严格解码。不要与其他界面测试并发；录制线程未正常退出或磁盘预留不足会失败并保留素材。结果位于新建的 `tests/artifacts/run-时间/`；`platform/devices.txt` 保存硬件环境。WAV 每条音轨约 1.29 GiB/小时，合成还需额外空间。

时长对齐、完整解码、正常进程和时钟模拟不足以证明内容口型同步。正式长测应准备每隔一分钟出现可见闪光及同步短音的独立外部信号，录制开始、中间、结束都测量声画边沿差值并记录初始偏移与累计漂移；不能只比较最终容器时长。

## 实体声卡检查

1. 在「声音」页分别测试「系统默认」和指定端点。播放有声内容或对麦克风说话，确认电平和保存的声音。
2. 录制中拔掉选中设备 10–30 秒。视频继续，声音页显示设备不可用，缺口静音；插回后约 2 秒重试并恢复，不应重复开启浮窗或提前保存。
3. 默认模式切换 Windows 默认播放 / 录音端点，新设备应被跟随；指定设备模式更换系统默认端点，仍录原设备。
4. 重连后改变设备格式（如 44.1 kHz 单声道与 48 kHz 双声道），检查文件保持统一时间线、声音不串轨。设备本身不支持在线更改时记录系统限制。
5. 在拔插同时暂停、继续、停止或退出，检查无卡死；成片完全解码，原文件不覆盖；设备缺失时停止也能完成。

## 多屏检查

在不同 DPI 屏幕间拖动主窗口和录制浮窗，反复最大化 / 还原，所有按钮应完整可见。区域边框必须与物理裁切坐标一致，负坐标副屏与跨屏区域都要检查；内部鼠标穿透，外侧拖动 / 八点缩放有效。开始录制前只有虚线，开始后才显示录制浮窗。

修改屏幕缩放只改变界面大小，不应缩放保存的物理选区。真实显示布局 / 目标窗口尺寸变化仍按保护策略停止并保存，不能宣称支持录制中无缝改变屏幕布局。

## 已知边界

自动降帧仍通过重启编码器完成，会有间隔；没有自动降低分辨率。界面时间 / 体积分组规则不是每个成片的严格大小上限。
